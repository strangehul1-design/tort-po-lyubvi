# Фотографии сайта

Здесь лежат исходники. На сайт выкладываются только облегчённые
копии из `web/` — их собирает скрипт.

## Две папки, два назначения

### `prices/` — торты из прайса

**Порядок здесь смысловой.** N-й файл по имени — это торт из N-й
строки прайса, который прислала кондитер. Поэтому имена нумерованные:
`01.png` — первая строка (8 кг, 40–45 гостей, 26 000 ₽), `09.png` —
девятая (8 кг, 40–45 гостей, 29 000 ₽).

Соответствие цены и номера строки прописано в `assets/catalog.js`
полем `pos`. Перепутаете файлы — фотография уедет к чужой цене,
и никакой скрипт этого не заметит.

### `gallery/` — кадры со свадеб

Снимки с самих свадеб для галереи под отзывами. Порядок любой,
берётся по имени файла.

## Как обновить

1. Положите файлы в нужную папку.
2. Запустите из корня проекта:

       powershell -ExecutionPolicy Bypass -File tools/gallery-manifest.ps1

3. Пересоберите карточки, если менялся состав прайса:

       node tools/gen-cards.mjs

Первый скрипт развернёт кадры, снятые боком (по EXIF), сложит в `web/`
по две копии каждого — на 800px для страницы и на 1600px для просмотра
во весь экран — и перепишет `assets/gallery.js`.

## Почему копии, а не оригиналы

Исходники со свадеб весят по мегабайту и больше — вместе почти
двадцать. Если отдавать их как есть, посетитель с телефона выкачает
эти двадцать мегабайт ради страницы, которую пролистает за минуту.
Копии на 800px весят около сотни килобайт, и браузер сам выбирает
по `srcset`, какую версию скачать; полный кадр подтягивается только
при открытии во весь экран.

Размеры копий записываются в манифест и попадают в `width`/`height`
картинки. Поэтому браузер знает пропорции заранее и вёрстка не
дёргается, пока снимки грузятся.

## Что попадает в репозиторий

Только `web/` и этот файл. Оригиналы перечислены в `.gitignore` и
остаются на вашем диске. Чтобы пересобрать галерею на другой машине,
скопируйте туда исходники и запустите скрипт заново.
