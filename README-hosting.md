# Перенос сайта на asiyatort.ru

Сайт переезжает с GitHub Pages на обычный хостинг в России со своим доменом.
Главное, ради чего переезд: заявки с телефонами клиентов сохраняются
на сервере в России (152-ФЗ), а не у Cloudflare.

## Что уже готово в репозитории

| Что | Зачем |
|---|---|
| `backend/submit.php` | принимает заявки: сначала записывает на диск хостинга, потом шлёт в Telegram |
| `backend/requests.php` | список заявок по ключу — если Telegram что-то не доставил |
| `backend/config.example.php` | образец файла с ключами (сам файл с ключами — только на хостинге) |
| `assets/api.js` | на asiyatort.ru формы шлют в `/backend/submit.php`, на старом адресе — как раньше |
| `.github/workflows/deploy.yml` | выкладка на хостинг после каждого пуша (выключена, пока её не включить) |
| `.htaccess` | закрывает служебные файлы от посторонних |

Пока домен не заработал, на нынешнем сайте ничего не меняется.

---

## 1. Домен на REG.RU

1. Зарегистрируйте `asiyatort.ru` **на Асию** — владельцем домена считается тот,
   чьи данные указаны при регистрации.
2. Дополнительные услуги не нужны: платный SSL, конструктор сайтов, почта,
   «скрытие данных» (у частных лиц в зоне .ru данные в WHOIS и так скрыты).
3. REG.RU может попросить подтвердить данные владельца (Госуслуги или паспорт).
   Сделайте это сразу: без подтверждения домен могут приостановить.

## 2. Хостинг

Нужен самый младший тариф виртуального хостинга. Сайт весит несколько мегабайт.

Требования:
- серверы в России;
- PHP 8.1 или новее с модулем curl (есть почти везде по умолчанию);
- бесплатный SSL-сертификат Let's Encrypt;
- доступ по FTP.

Подойдут Beget, Timeweb или хостинг самого REG.RU.
Если хостинг тоже на REG.RU, шаг 3 почти не нужен — домен привяжется сам.

## 3. Привязка домена к хостингу

1. В панели хостинга добавьте сайт `asiyatort.ru`. Хостинг покажет
   адреса своих DNS-серверов (обычно 2–4 строки вида `ns1.…`).
2. В REG.RU: карточка домена → «DNS-серверы и управление зоной» →
   изменить → свой список DNS-серверов → вписать адреса хостинга.
3. Изменения расходятся по интернету от пары часов до суток.

## 4. SSL

В панели хостинга выпустите бесплатный сертификат Let's Encrypt для
`asiyatort.ru` и `www.asiyatort.ru`. Когда он выпущен — включите там же
перенаправление на HTTPS и с `www` на адрес без `www`, если есть такие переключатели.

## 5. Ключи для заявок

Ключи **никогда** не отправляются в чат и не кладутся в репозиторий.

1. В файловом менеджере хостинга найдите папку сайта (часто `public_html`
   внутри папки `asiyatort.ru`).
2. **Рядом** с ней — на уровень выше, не внутри — создайте файл `tort-config.php`.
   Так его нельзя открыть по ссылке из браузера.
3. Скопируйте в него содержимое `backend/config.example.php` и впишите:
   - `TELEGRAM_BOT_TOKEN` — токен бота от @BotFather (тот, что сейчас в Cloudflare);
   - `TELEGRAM_CHAT_ID` — кому слать заявки, несколько — через запятую;
   - `ADMIN_KEY` — придуманный длинный пароль для просмотра списка заявок.

Заявки сохраняются в папку `tort-requests` там же, рядом с папкой сайта.
Через 180 дней они удаляются сами — так написано в политике.

## 6. Автоматическая выкладка из GitHub

Сайт выкладывается на хостинг сам после каждого пуша в `main`.

1. GitHub → репозиторий → Settings → Secrets and variables → Actions →
   **New repository secret**, четыре секрета:

   | Имя | Что вписать |
   |---|---|
   | `FTP_SERVER` | адрес FTP-сервера из панели хостинга |
   | `FTP_USERNAME` | логин FTP |
   | `FTP_PASSWORD` | пароль FTP |
   | `FTP_DIR` | путь к папке сайта с косой чертой в конце, например `asiyatort.ru/public_html/` |

2. Там же, вкладка **Variables** → New repository variable:
   `DEPLOY_ENABLED` = `true`.
3. Actions → «Выкладка на хостинг» → Run workflow. Первая выкладка
   загружает всё, следующие — только изменённые файлы.

На хостинг не попадают: `api/` (прежний сервер), `tools/`, демо-оплата,
файлы README.

## 7. Проверка после запуска

| Что открыть | Что должно быть |
|---|---|
| `https://asiyatort.ru` | сайт открывается, в адресной строке замок |
| `https://asiyatort.ru/backend/lib.php` | «Доступ запрещён» (403) |
| `https://asiyatort.ru/backend/requests.php` | «Not found» (404) — без ключа список закрыт |
| форма «Заявка на торт» с именем «Тест» | заявка пришла в Telegram |
| `https://asiyatort.ru/backend/requests.php?key=ВАШ_ADMIN_KEY` | в списке есть тестовая заявка |

Если заявка не пришла в Telegram, но есть в списке — неверный токен или
номер чата в `tort-config.php`. Заявка не потеряна: она дошлётся
вместе со следующей, как только ключи будут исправлены.

## 8. После запуска

Это делается в коде, когда сайт уже открывается по новому адресу:

- адрес `https://asiyatort.ru` в `canonical`, `og:url`, `sitemap.xml`,
  `robots.txt`, разметке для поисковиков, ссылке в оферте;
- политика обработки данных: хранение — на хостинге в России,
  Cloudflare и GitHub из раздела о хранении убрать;
- старый адрес на GitHub Pages — переадресация на новый домен,
  чтобы в поиске не было двух одинаковых сайтов;
- Яндекс.Вебмастер: добавить сайт и отправить `sitemap.xml`;
- уведомление в Роскомнадзор: указать хостинг и место хранения данных — Россия.

## Прежний сервер на Cloudflare

Он остаётся для правок текста через Telegram-бота и для старого адреса,
пока идёт переезд. В `api/worker.js` исправлена заявка на дегустацию:
раньше в Telegram не попадали способ получения сета и адрес доставки.
Чтобы исправление заработало, его нужно выложить:

```bash
cd api
npx wrangler deploy
```
